# LUSI Wedding — тёмная editorial-версия

Сайт свадебного агентства, собранный по макету
`refs/lusi-editorial-dark.png`.

Раньше рядом жила первая, светлая версия: этот код лежал в подпапке
`ver2/`, а над ним — отдельный проект со своими зависимостями. Заказчица
выбрала тёмный вариант, светлый удалён, и его код поднят в корень. Если
в старых заметках попадётся путь вида `ver2/src/...` — это здесь, просто
без первого сегмента. То, что осталось от первой версии для справки
(её README, светлые референсы, исходный HTML-макет агентства), лежит в
`_archive/` и в репозиторий не входит.

## Публикация

Сайт публикуется на **Timeweb** статической выгрузкой — без Node на
стороне хостинга.

```bash
npm run build:static
```

Кладёт готовый сайт в `out/`. Эту папку целиком загружают в корень
сайта: по FTP или архивом через файловый менеджер. Внутри уже лежит
`.htaccess` со страницей 404, сжатием и сроками кэша.

Что нужно знать про этот режим:

- **оптимизатора картинок нет** — он серверный. `next/image` отдаёт
  файлы как есть, поэтому телефон получит те же кадры, что и десктоп.
  Кадры в `public/images` подготовлены под свои размеры, так что
  выглядит правильно, но весит больше: выгрузка занимает 25 МБ, из них
  23 МБ — фотографии;
- всё остальное работает: меню, карусель свадеб, раскрытие тарифов,
  проверка формы. Шрифты next/font кладёт рядом, к Google они не ходят.

Если на Timeweb вместо статики поднимут облачное приложение с Node,
эта сборка не нужна — там обычные `npm run build` и `npm start`.

## Запуск

```bash
npm install
npm run dev      # http://localhost:3100
npm run build
npm run lint
```

Порт 3100, а не привычный 3000: так повелось с тех пор, когда рядом
была запущена первая версия. Менять его смысла нет — он прописан в
`.claude/launch.json` и в скриптах `package.json`.

## Карточка свадьбы

Клик по кадру в портфолио открывает развёрнутую карточку: обложка,
дата, название проекта, четыре факта (палитра, площадка, число гостей,
формат), рассказ о вечере в две колонки и галерея. Внизу — переход
к предыдущей и следующей свадьбе.

Кадров в галереях: 12, 13, 15 и 11 — сетка сама раскладывает их парами,
а широкие снимки (`span: 2`) занимают всю строку. Порядок в массиве
подобран так, чтобы строки закрывались без одиночного кадра в конце:
если будете добавлять или убирать снимки, следите за чётностью обычных
кадров между широкими.

Свадеб четыре, все с реальными фотографиями из папки `weddings/`.

Карточка живёт в нативном `<dialog>`: браузер сам уводит в неё фокус,
закрывает по Escape и прячет остальную страницу от скринридера. Файлы:

- `content/works.ts` — данные свадеб;
- `portfolio/WorksGallery.tsx` — сетка, состояние и само окно;
- `portfolio/WorkDetails.tsx` — содержимое карточки. Оно ничего не знает
  ни про `<dialog>`, ни про состояние, поэтому его можно без правок
  положить на отдельную страницу, если раздел вырастет.

Чтобы добавить свадьбу, достаточно дописать объект в массив `works` —
счётчик, переходы и сетка подхватят её сами.

## Карусель свадеб на телефоне

До 640px портфолио показывается стопкой с глубиной: карточки уходят
назад и вправо, смахивание листает, нажатие на переднюю открывает
карточку свадьбы целиком. С 640px её сменяет обычная сетка — оба
варианта лежат рядом в `WorksGallery.tsx`, разведённые по `sm:`.

Стопка зациклена: ушедшая карточка возвращается в конец очереди,
листать можно бесконечно в обе стороны.

Анимация покадровая (`requestAnimationFrame`), а не на CSS-переходах,
и это принципиально. При зацикливании карточка в какой-то момент
перескакивает с начала кольца в конец; CSS-переход отыграл бы этот
перескок прокруткой через всю стопку. Пересчитывая раскладку каждый
кадр, мы проводим карточку через точку перескока плавно — и делаем это
там, где она полностью прозрачна. Библиотека для этого не нужна: весь
tween — десяток строк.

Что заложено в поведении:

- **один жест — одна карточка.** Ограничение стоит не только на
  отпускании, но и на самом перетаскивании: палец уводит стопку максимум
  на позицию, дальше идёт сопротивление. Иначе длинным смахиванием
  прокручивались все свадьбы разом, а на отпускании стопку отбрасывало
  назад — и это читалось как поломка;
- **кольцо вдвое длиннее списка.** Прозрачность обязана падать до нуля
  на половине кольца — там точка перескока. При четырёх карточках это
  d = 2, и в стопке остаётся всего два видимых слоя. Проходим круг
  дважды: половина уезжает на d = 4, слоёв становится четыре. Свадьба
  попадает в кольцо дважды, но второй раз — ровно в невидимой точке;
- **`touch-action: pan-y`** — вертикальная прокрутка страницы остаётся
  за страницей, горизонтальные движения достаются карусели;
- **`overflow: hidden` у стопки** — карточки в глубине смещены вправо
  и без обрезки растягивали страницу по горизонтали;
- **порог в 5px** отделяет нажатие от перетаскивания, иначе карточка
  открывалась бы при каждом смахивании;
- **полосок-указателей под стопкой нет** — их убрали как лишний шум.
  Взамен стопка принимает фокус и листается стрелками: иначе до
  остальных свадеб было бы не добраться без пальца.

## Меню на телефоне

Это **StaggeredMenu из React Bits**, поставленный из реестра:

```bash
npx shadcn@latest add @react-bits/StaggeredMenu-JS-CSS
```

Исходник лежит в `src/components/reactbits/` и намеренно почти не
правится — так его можно обновить одной командой. Тянет за собой `gsap`.

Что сделано вокруг него:

- **`layout/SiteMenu.tsx`** — обёртка с нашими пунктами, цветами шторок
  (золотая и тёмно-винная) и золотым логотипом. Логотип компонент
  вставляет тегом `<img>`, поэтому нашу CSS-маску сюда не подать и для
  него подготовлен готовый файл `public/logo-gold.png`.
- **Переопределения стилей** — в конце `globals.css`, вне `@layer`:
  слои Tailwind проигрывают обычным правилам, а компонент приходит со
  своим CSS-файлом. Там панель перекрашена в винный, пункты переведены
  на нашу антикву без капса, номер перенесён влево.
- **`reactbits/StaggeredMenu.d.ts`** — типы пропсов. Компонент на
  JavaScript, и TypeScript выводит тип `items` из значения по умолчанию
  `[]`, то есть `never[]` — передать в него что-либо иначе невозможно.

Правки в самом исходнике — три, при обновлении из реестра их придётся
вернуть:

1. русские подписи кнопки (`Menu`/`Close` → `Меню`/`Закрыть`)
   и `aria-label`;
2. проп `panelFooter` — точка вставки своего блока в низ панели
   (штатный `displaySocials` рисует заголовок «Socials» и ждёт готовые
   адреса, а сноску про Meta вставить в него некуда);
3. проп `logoHref` — логотип в шапке компонента был просто картинкой
   и никуда не вёл. Теперь оборачивается в ссылку; там, где `logoHref`
   не передан, остаётся картинкой, как было.

### Чего компонент не делает

Три вещи пришлось добавить снаружи, в `SiteMenu.tsx`:

- **не блокирует прокрутку** страницы под открытым меню — вешаем свой
  замок через колбэки `onMenuOpen` / `onMenuClose`;
- **не закрывается по Escape.** Метода закрытия наружу компонент не
  отдаёт, поэтому по Escape программно нажимаем его же кнопку;
- **не закрывается при переходе по пункту** — у ссылок в панели нет
  обработчика, и меню оставалось раскрытым поверх нужного раздела.
  Ловим клик по панели и закрываем той же кнопкой, до того как браузер
  отработает переход к якорю;
- **оставляет ссылки панели в порядке обхода табом, когда меню
  закрыто.** Панель помечена `aria-hidden`, но ссылки в ней остаются
  фокусируемыми: скрытая от скринридера, но доступная с клавиатуры
  ссылка — ловушка. Закрытой панели проставляется `inert`.

Блокировка прокрутки живёт в `lib/scroll-lock.ts` и используется ещё и
карточкой свадьбы. Помимо `overflow: hidden` она возвращает ширину
исчезнувшей полосы прокрутки полем справа — иначе страница вместе с
липкой шапкой прыгает вбок в момент открытия.

## Команда

На телефоне пятеро идут одной лентой, которая листается пальцем: в сетке
из двух колонок они занимали три экрана. Лента вынесена за контейнер на
ширину поля (`-mx-(--gutter) px-(--gutter)`), поэтому карточки уезжают
под край экрана, а первая всё равно встаёт по общей левой линии.

Прокрутка нативная, со `scroll-snap` — никакого JavaScript. Полосу
прокрутки прячет утилита `.rail` в `globals.css`, а `scroll-pl` держит
привязку по тому же полю. С 640px лента снова становится сеткой:
по трое на планшете, впятером в ряд на широком экране.

## Плавное раскрытие <details>

Нативный `<details>` открывается рывком. Класс `.disclosure`
(`globals.css`) разгоняет высоту через псевдоэлемент
`::details-content`, а `interpolate-size: allow-keywords` на `:root`
разрешает анимировать переход к `height: auto` — без него высоту
неизвестного заранее блока не проанимировать.

`content-visibility` переключается дискретно, поэтому ему передан
`allow-discrete`: иначе содержимое исчезало бы в первый же кадр
закрытия и высота ехала бы по пустоте.

Где браузер не знает `::details-content`, блок откроется мгновенно, как
и раньше. Класс висит и на тарифах, и на списках внутри них.

## Форматы

Три тарифа без карточек и заливок: колонки разделены волосяными линиями,
как остальные сетки на сайте. Популярный формат выделен только золотом —
надписью «Чаще всего выбирают» и залитой кнопкой.

До 1024px тарифы показываются раскрывающимся списком
(`sections/PackagesList.tsx`): в свёрнутом виде название, на сколько
человек формат и цена, подробности открываются по нажатию. Три полные
колонки на телефоне вытягивались в одно длинное полотно, и сравнить
форматы было нельзя. Атрибут `name` у `<details>` делает список
взаимоисключающим — открыт всегда один тариф.

Колонки на широком экране выровнены построчно через `grid-rows-subgrid`: описания у трёх
форматов разной длины, и без этого цена, списки и кнопки стояли бы на
разной высоте. У каждой колонки должно быть **ровно семь прямых
потомков** — надпись, название, аудитория, описание, цена, списки,
кнопка. Добавите восьмой блок — не забудьте увеличить число строк
в `grid-rows-[…]` у родителя и `row-span-7` у колонки.

Разделители сделаны боковыми полями, а сетка вынесена за контейнер
на ту же величину (`lg:-mx-10`). Без этого у средней колонки поля с двух
сторон, а у крайних с одной, и она получается уже соседних — длинные
надписи в ней начинают переноситься.

Раскрывающиеся списки — нативные `<details>`, без JavaScript: работают
с клавиатуры и открываются даже при выключенных скриптах.

**Содержимое списков — черновик.** На присланном макете тарифов эти три
блока были свёрнуты, и их текста не видно. Названия, аудитория, описания
и цены — данные заказчика, а вот что именно входит в тариф, кто в команде
и какие есть дополнительные возможности, я составил по логике услуги.
Перечень услуг в тарифе — коммерческое обязательство, поэтому до
публикации его нужно заменить настоящими формулировками.

## Мессенджеры и соцсети

`ui/Socials.tsx` — три кнопки в одну строку и сноска под ними. Блок
выводится дважды: внизу панели меню и в подвале. Поэтому у него есть
проп `place` — идентификатор сноски должен быть уникальным, иначе
скринридер не свяжет с ней помеченные кнопки.

Кнопки текстовые, без фирменных значков: на сайте нет ни одной иконки,
кроме стрелки и плюса, и три чужих логотипа выпадали бы из набора.
Кегль, трекинг и поля здесь мельче, чем у капса на остальном сайте, —
иначе три кнопки не встают в строку на экране 360px.

**Ссылок пока нет** (`href: null` в `content/site.ts`), кнопки рисуются
неактивными: ссылка в никуда хуже честной заглушки. TODO: подставить
адреса аккаунтов.

**Сноска про Meta.** Instagram и WhatsApp помечены звёздочкой, под
рядом идёт пояснение. Формулировку стоит показать юристу: в России
запрещена деятельность самой Meta и заблокирован Instagram, тогда как
WhatsApp не заблокирован — он просто принадлежит той же компании.
Текущий текст сформулирован именно так и лежит в `socialsNote`.

## Форма заявки

Блок «Рассказать о своей свадьбе» — форма из четырёх полей: имя и
контакт обязательные, дата и комментарий нет, плюс чекбокс согласия
на обработку данных. Проверка своя, а не браузерная: тексты ошибок
лежат в `leadForm` в `content/site.ts`, у полей проставлены
`aria-invalid` и `aria-describedby`, результат объявляется через
`role="status"`.

**Форма пока никуда не отправляет.** В `Cta.tsx` вверху есть константа:

```ts
const LEAD_ENDPOINT: string | null = null;
```

Пока она `null`, форма проверяет поля и честно пишет, что не подключена
к почте. Делать вид, что заявка ушла, нельзя — человек будет ждать
ответа, которого не будет. Как только здесь появится адрес обработчика,
форма начнёт слать `POST` с JSON `{name, contact, date, message}`,
и больше ничего менять не нужно.

| `cream` | `#f7f2e9` | Текст на тёмном фоне |

Шрифты — три, каждый со своей работой:

- **Bodoni Moda** — вордмарк «LUSI WEDDING» и цифры 01–04. Настоящая
  дидона: толстые основные штрихи и волосяные соединительные. Ось
  оптического размера выкручена в 96 (`.font-display` в `globals.css`) —
  на крупном кегле шрифт рисует более тонкие линии. **Кириллицы в нём
  нет** (доступны только latin, latin-ext, math, symbols), русский текст
  им набирать нельзя.
- **Cormorant** — русские заголовки, 400. Тот же высокий контраст, что
  у Bodoni, но с кириллицей.
- **Tenor Sans** — меню, кнопки, подписи, основной текст. Только
  начертание 400: полужирного нет, и опираться на него в вёрстке нельзя,
  иначе браузер нарисует поддельный.

До этой связки пробовали Prata (на кегле 240px её плотные штрихи
выглядели грубо) и Alumni Sans (слишком узкая и тонкая для абзацев).

Кегль вордмарка привязан к метрикам конкретного шрифта: он подобран так,
чтобы «WEDDING» доходило ровно до правого края окна на 1440px. При смене
гарнитуры это значение и обе вертикальные позиции в `Hero.tsx` нужно
пересчитывать — ширина буквы в em у каждого шрифта своя.

`public/_fonts.html` — временная страница сравнения гарнитур
(`/_fonts.html` на дев-сервере). Удалить перед публикацией.

Композиция держится на переменных `--gutter`, `--section-y`,
`--header-h` и контейнере `--container-site` (1240px чистого контента,
поля добавляются сверх этой ширины — так колонка совпадает с макетом).

## Логотип

Исходник `logo.jpg` — чёрный знак на белом фоне, на тёмной шапке он
непригоден. Из него сделан `public/logo.png`: белые пиксели переведены в
прозрачность, изображение обрезано по знаку. В вёрстке файл используется
не как картинка, а как CSS-маска (`.logo-mask` в `globals.css`), поэтому
знак принимает текущий цвет текста — золотой в шапке, кремовый в меню.

Если знак когда-нибудь перерисуют, достаточно заменить `public/logo.png`
на новый PNG с прозрачным фоном той же пропорции (579 × 117).

## Фотографии

Заполнено всё, кроме портретов команды (`images/team/`) — их пока нет,
и на их месте стоят заглушки с именами ожидаемых файлов. Оригиналы лежат в `weddings/`
(четыре папки по номерам свадеб, 173 МБ) — они **не** попадают в
репозиторий: в `public/images/` уже лежат те же кадры в веб-размере,
сжатые до 17 МБ.

| Раздел | Путь | Пропорция |
| --- | --- | --- |
| Первый экран, десктоп | `images/hero-couple.jpg` | 16:9 |
| Первый экран, телефон | `images/hero-couple-mobile.jpg` | 9:16 |
| Заявление | `images/statement-table.png` | 4:3, вырезан |
| Киноплёнка, 6 шт. | `images/film/01…06-*.jpg` | 9:8 |
| Команда, 5 шт. | `images/team/01…05-*.jpg` | 4:5 |
| Процесс | `images/process-veil.jpg` | 15:16 |
| Обложки свадеб | `images/works/<свадьба>/cover-*.jpg` | 3:4 |
| Обложки карточек | `images/works/<свадьба>/hero*.jpg` | 16:9 |
| Галерея, широкие | `…/01`, `…/04`, `…/07`, `…/12` | 3:2 |
| Галерея, вертикальные | `…/02`, `…/03`, `…/08`–`…/13` | 3:4 |
| Галерея, квадратные | `…/05`, `…/06`, `…/14`, `…/15` | 1:1 |

Точный состав у каждой свадьбы свой — смотрите массив `gallery`
в `content/works.ts`.

Папки свадеб: `otrazhenie`, `sad-u-vody`, `tysyacha-svechey`,
`siniy-vecher`.

Обесцвечивание делает CSS (`mono` у `MediaFrame`) — присылать
чёрно-белые файлы не обязательно.

Если предмет вырезан и лежит на прозрачном фоне (как стол в блоке
«Заявление»), у слота ставится `cutout: true`. Тогда `MediaFrame` не рисует
подложку и обводку и вписывает кадр целиком через `object-contain` —
иначе `object-cover` срезал бы предмету края.

### Как добавить новую свадьбу

1. Уменьшить кадры: обложка 1200×1600 (ровно 3:4 — см. ниже),
   обложка карточки 2400px по ширине,
   широкие кадры галереи 2000px, остальные 1300px; JPEG качества 82.
2. Положить в `public/images/works/<новый-slug>/`.
3. Дописать объект в массив `works` в `src/content/works.ts` — счётчик,
   переходы и сетка подхватят его сами.

Все четыре свадьбы стоят в один ряд от 1024px, по две от 640px и по
одной на телефоне. Подпись — дата и название — стоит под кадром и видна
сразу, а не по наведению: при наведении кадр слегка приближается
и уезжает стрелка.

Портфолио — единственная секция, которая выходит за общий контейнер
на всю ширину окна: в четыре колонки внутри 1240px превью получались
мелкими. Заголовок выровнен по тому же полю, что и карточки.

### Разрешение исходников

Кадры отдаются через `next/image` с `quality={90}` (значение по умолчанию,
75, заметно мылит тёмные градиенты; допустимые значения перечислены в
`next.config.ts`).

Для первого экрана нужен широкий файл: он растянут на всю ширину окна.
Текущий `hero-couple.png` — 1672 × 941, этого хватает до окна ~1670px.
На более широких мониторах кадр растягивается и мылится, поэтому для
публикации нужен исходник от 2560px по ширине (лучше 3200px, чтобы
хватило и на экраны с удвоенной плотностью).

### Первый экран: два файла вместо одного

Горизонтальный кадр 16:9 в высокой рамке телефона обрезался до
неузнаваемости — оставались лоб жениха и плечо невесты. Поэтому кадров
два: `hero-couple.jpg` для широких экранов и `hero-couple-mobile.jpg`
для телефона, один и тот же снимок в разном кадрировании.

Подставляет их обычный `<picture>` с `media`, а не `next/image`:
next/image меняет размер файла, но не сам файл, и художественное
кадрирование ему недоступно. Оба файла уже подготовлены под свои
пропорции, так что оптимизация здесь ничего не добавила бы. Это
единственное место на сайте, где кадр идёт мимо `MediaFrame`.

Ещё на телефоне под вордмарком лежит градиентная подложка (`lg:hidden`):
низ вертикального кадра занимает светлое платье, и золото с кремовым на
нём пропадали. На широких экранах вордмарк лежит на тёмных портьерах,
и там затемнения нет — первый экран остался таким, как утверждали.

### Кадрировать заранее, а не в CSS

Если пропорция файла не совпадает с рамкой, `object-cover` тянет кадр
по недостающей стороне — и запрашивает у браузера меньше пикселей, чем
ему нужно. Горизонтальный снимок в вертикальной обложке 3:4 растягивался
на две трети и заметно мылил. Поэтому обложки свадеб вырезаны в 3:4
заранее, файлом: пропорции совпадают, `object-cover` ничего не делает,
и запаса по ширине не требуется.

### Имена файлов при замене кадра

Меняете содержимое картинки — **меняйте и имя файла**. Путь остаётся
прежним, и браузер вместе с оптимизатором Next продолжают отдавать
старую версию: на диске новый кадр, на экране прежний. Отсюда имена
вида `cover-photozone.jpg`, `cover-ceremony.jpg` — они заодно
подсказывают, что на кадре.

### Про `sizes` у полноэкранных кадров

Атрибут `sizes` описывает **ширину** места под фотографию, но `object-cover`
в высокой рамке растягивает кадр по **высоте**. На телефоне рамка первого
экрана втрое выше своей ширины, поэтому честное `100vw` заставляло браузер
скачивать файл шириной 828px и растягивать его вдвое. Отсюда `400vw` в
`Hero.tsx`: значение с запасом, лишнего браузер всё равно не возьмёт —
оптимизатор не выдаёт больше, чем есть в исходнике. У остальных кадров
пропорция рамки совпадает с пропорцией снимка, там `sizes` обычный.

## Отступления от макета и почему

- **Подписи в портфолио.** На макете кадры безымянные. Пара, площадка и
  год проявляются при наведении и по фокусу с клавиатуры: композиция в
  покое не меняется, но кадры перестают быть анонимными.
- **Описания шагов.** В макете у блока «Процесс» только цифры и
  названия. Добавлена строка пояснения под каждым — иначе раздел не несёт
  информации. Убирается удалением поля `text` в `content/site.ts`.
- **Абзац в блоке «Заявление».** Тоже добавлен: на макете под заголовком
  пустое место.
- **Подвал.** В макете его нет, но сайту нужен блок с контактами и якорь
  для ссылки «Контакты» в меню.
- **Вордмарк на широких экранах.** Кегль и высота первого экрана
  перестают расти после 1440px, иначе композиция уезжает вправо от
  контейнера.

## Что ещё не сделано

- **Контакты не заполнены** — в подвале стоит «уточняется».
  Правится в `contacts` в `src/content/site.ts`.
- **Форма заявки не подключена** — см. `LEAD_ENDPOINT` выше.
- **Списки внутри тарифов — черновик** (`content/packages.ts`), см. выше.
- **Согласие на обработку данных ссылается в пустоту.** Чекбокс в форме
  есть, а страницы политики нет. До запуска формы её нужно написать
  и привязать к чекбоксу ссылкой.
- **Тексты черновые** — заявление, описания шагов и подписи к работам
  написаны под макет и требуют вычитки заказчиком.
- **Портфолио нужно сверить.** Фотографии и даты достоверны: даты взяты
  из имён файлов и подтверждаются кадрами (у первой свадьбы дата
  напечатана в фотозоне, у третьей — на экране в зале). А вот что
  требует подтверждения заказчиком:
  - **названия проектов.** «Отражение двух миров» снято с самой
    фотозоны, три остальных названы по визуальной теме и являются
    рабочими;
  - **имён пар в данных нет.** Они не выдуманы и не подставлены —
    их просто нет. Публиковать имена и лица можно только с письменного
    согласия пар;
  - **площадки и число гостей** — стоит «уточняется»;
  - **список задач агентства** описывает то, что видно на кадрах, но не
    заменяет договор.
- **Политики конфиденциальности нет** — она понадобится вместе с формой.

## Соглашения

- Русская типографика расставляется автоматически: `typoDeep` для данных
  из `content/*`, компонент `<Typo>` для текста в разметке. Неразрывные
  пробелы в исходниках не пишем — их не видно при правке.
- Классы Tailwind в квадратных скобках нельзя писать внутри комментариев
  в JSX: сканер подхватит их и сгенерирует мусорный CSS.
- Появление блоков при прокрутке — компонент `Reveal`. Без JS содержимое
  остаётся видимым (стиль под `<noscript>` в `layout.tsx`).
